# 学习与创作体验

Breakfix 的核心体验是：用户在真实、可回收的运行环境中理解或处理一个明确场景；平台持续展示公开检查点，而不是要求用户点击提交。
内容有两种独立方向：阅读上游文档时使用的可执行示例，以及由运维人员复现和分享的运维场景。二者共享运行底座，组织和发布标准
各自独立。

## 题库与工作台

Catalog 展示当前 active revision 的场景摘要，可按全文搜索、简单标签和必要运行属性筛选。登录用户能看到完成、进行中和检查点
进度；未登录用户只能浏览摘要。卡片展示标题、描述、类型、标签、runtime 与发布时间。页面不展示难度、课程层级或场景关系图。

开始场景进入固定工作台：左侧显示 Problem、Solution、Assistant 和公开检查点，右侧是浏览器终端。Problem、Solution 和提示服务于
同一组检查点；用户可以打开多个终端窗口、重置环境或停止场景。页面本身不应滚动，正文、助手消息和终端各自管理滚动区域。

检查点是周期性的自动判断。Controller 将当前结果写入 Environment status，工作台和目录读取这份权威状态；所有检查点通过后场景
自动完成。没有用户可见的 Submit，也不要求用户上传结果。

## 终端上下文助手

助手是工作台中的文档面板，不遮挡终端。它按需调用只读工具读取指定 tmux 窗口近期 scrollback、Controller 保存的检查点快照、
当前环境文件，或在用户明确要求时读取参考解答。工具不修改用户环境。会话与 Environment UID 绑定；Stop、Reset 或环境回收会
清理相应对话，避免把旧环境上下文带到新场景。

## 作者工作台

作者在同一页面完成自然语言讨论、题意约定和已验证 revision 审核。修改题意或检查点只能通过 Agent 的受控领域操作，不能直接编辑
已发布场景文件。作者确认某个 Plan revision 后，Authoring Agent 创建 workflow、操作远程 workspace 并提交 candidate；Judge 与
`Build -> ArtifactPublish -> Verify` 由异步状态机推进。打回或验证失败的反馈返回作者对话，只有作者要求时才继续修复。

验证成功后，作者查看场景资产、检查点、diff 和验证摘要，并在对话中确认内容。确认后直接发布：对运维场景，标签来自 candidate
manifest 并随 immutable revision 发布；对文档示例，后续契约会把其上游文档位置作为单独来源元数据。平台不自动分类、不生成关系图。

## My Space

My Space 汇总当前用户的学习和创作事实：已完成与已尝试场景数、有效终端学习时长、进行中的环境、学习历史、进行中的作者会话以及
已发布内容的匿名聚合统计。它不复制 Catalog 到数据库；标题、runtime、类型与标签从对应 immutable revision 读取。

学习记录通过 Server 对 Environment status 的幂等投影保存，因此环境被 Stop、Reset 或闲置回收后，完成和尝试历史仍可见。终端学习
时长按环境级有效连接区间去重，多个 shell 不会重复累计。

## 产品边界

- 场景生成、验证和发布属于作者流程；学习者不上传 artifact。
- Solution 是学习资产，检查点是完成判断；两者不通过手动提交按钮耦合。
- Catalog、Workspace、My Space 和 Authoring 保持单页应用导航。
- 文档示例的上游 revision、页面路径和章节锚点属于后续文档实践化契约；它们不复用运维场景标签。
- 学习路径、推荐、排行榜、讨论区、付费和组织集成需要真实使用数据，当前方向见根目录 [`NEXT.md`](../../NEXT.md)。
