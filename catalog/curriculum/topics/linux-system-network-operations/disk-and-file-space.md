# 磁盘与文件空间

**Topic ID：**`disk-and-file-space`
**Domain：**Linux 系统与网络运维
**状态：**首轮核心场景设计，需可控文件增长与打开文件行为 probe

## 范围

本 Topic 处理“表面上空间或 inode 不足，但根因隐藏在运行状态中”的主机故障。修复要保留当前业务数据和日志语义，不能通过清空整个工作目录或扩容底层环境掩盖问题。

## 建议前置知识

Shell、文件与配置定位；日志与计划任务；进程与 systemd 服务。

## 学习导读

### 学习目标

- 区分数据块用量与 inode 用量，以及可见目录用量和进程持有空间的差异。
- 从文件系统症状追踪到具体进程或可安全清理的文件集合。
- 在保留当前业务数据和日志语义的边界内恢复写入能力。

### 核心心智模型

`df` 描述文件系统分配，`du` 描述当前目录树可见文件；两者不一致通常意味着挂载、删除但仍打开的文件或统计边界不同。大量小文件可以耗尽 inode，即使数据块仍有空间。

### 诊断证据与工具

比较 block 与 inode 使用率、目录用量、打开文件描述符和应用写入失败。先定义哪些文件是当前队列或活动日志，再进行清理，避免把“腾出空间”变成数据丢失。

### 常见误区

- 看见空间不足就递归删除整个日志或工作目录。
- 只看 `df -h`，忽略 inode 使用率。
- 删除已打开日志后不处理仍持有它的进程。

### 面试追问

- `df` 已满、`du` 却很小，最常见的调查路径是什么？
- inode 耗尽与磁盘块耗尽在应用层各如何表现？

### 推荐关系

建议在日志、进程和文件定位 Topic 之后学习；挂载与 LVM 场景等待独立能力验证。

## 核心场景

### `reclaim-deleted-orders-log`：回收仍被打开的已删除日志

- **环境地图：**`app` 上的 `orders-api.service` 持续写入 `/var/log/orders-api/`；日志轮转后仍可能有旧文件由进程持有。
- **本题相关知识：**`df` 与 `du`、打开文件描述符、日志轮转、服务 reload/restart。
- **学习目标：**从空间统计差异定位 deleted-but-open 文件，并以不丢失当前日志语义的方式回收空间。
- **初始状态：**一次错误的日志轮转删除了大文件，但旧 `orders-api` 进程仍持有其文件描述符。根文件系统接近满，`du /var/log/orders-api` 的总量却显著小于 `df` 显示的已用空间。
- **用户看到的症状：**新请求开始失败或日志写入报空间不足；目录中找不到与已占空间相符的大文件。
- **任务边界：**通过受支持的服务与日志轮转方式释放已删除文件；不能删除当前活跃日志、重建整个文件系统或关闭应用日志。
- **完成条件：**文件系统恢复到安全可用空间，服务继续写入当前规范日志。
- **检查点：**可用空间高于题目阈值；已删除的大日志不再被进程持有；一次新请求写入当前 access log。
- **提示层级：**方向：比较文件系统统计与目录树统计；证据：定位持有已删除文件的进程；概念：删除目录项不会立刻释放仍由打开描述符引用的数据块。
- **解答与复盘：**由 `df`/`du` 差异识别隐藏空间，定位 `orders-api` 持有的已删除日志，并用受管服务生命周期释放描述符后确认新日志持续写入。生产中应将日志轮转与应用 reopen/reload 策略配套演练。
- **作者 verifier：**当前活跃日志未被删除；服务重启或 reload 后仍持续输出；不通过扩容或修改底层文件系统达成通过。
- **能力状态：**需“单机运维主机”中稳定的文件日志与进程行为。

### `recover-inode-exhaustion`：恢复 inode 可用量

- **环境地图：**`ops` 上的 `orders-worker` 在 `/var/lib/orders-worker/tmp` 写入临时文件，并在完成后保留当前队列文件。
- **本题相关知识：**inode、目录项、小文件、临时文件生命周期。
- **学习目标：**在块空间充足时识别 inode 耗尽，并区分历史临时文件和仍需保留的工作文件。
- **初始状态：**`orders-worker` 的临时目录累积了大量历史小文件，导致文件系统 inode 耗尽；数据块空间仍充足。当前队列中的少数近期文件必须保留。
- **用户看到的症状：**worker 创建临时文件时报 `No space left on device`，但 `df -h` 显示磁盘并未写满。
- **任务边界：**只清理已识别的历史临时产物；不能删除当前队列、扩大磁盘或以修改 worker 跳过持久化。
- **完成条件：**inode 重新可用，worker 能创建新工作文件，当前队列保持完整。
- **检查点：**inode 使用率降至题目阈值以下；worker 成功完成一次真实维护任务；当前队列文件仍可被读取。
- **提示层级：**方向：当块空间正常时，检查文件系统的另一种耗尽维度；证据：比较 inode 使用率、文件数量和临时目录生命周期；概念：每个目录项消耗 inode，与文件内容大小无关。
- **解答与复盘：**确认失败来自 inode 而非容量，按明确的时间/命名边界清理历史临时产物，再让 worker 真实写入验证。生产中应为临时目录的文件数量和保留期设置管理策略。
- **作者 verifier：**当前队列和非临时文件未被清理；没有通过扩容或跳过持久化达成通过；后续 worker 运行保持正常。
- **能力状态：**需“单机运维主机”中有界的小文件生成与清理机制。
